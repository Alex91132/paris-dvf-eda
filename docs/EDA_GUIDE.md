## 0. Что должно получиться

Хороший EDA отвечает на вопросы, а не описывает таблицу. На выходе нужны:

- **воронка очистки**: сколько строк было, сколько осталось и почему;
- **5–10 гипотез**, у каждой есть метрика, статистическая проверка и вывод с доверительным интервалом;
- **хотя бы одна «ловушка»**: вывод, который наивный анализ получает неверно, и объяснение, почему;
- **воспроизводимость**: одна команда пересобирает все числа и графики из сырых данных;
- **отчёт** для человека (HTML или ноутбук) и **сводка чисел** для машины (JSON).

Плохой EDA — это 40 гистограмм подряд, `df.describe()` и фраза «видна корреляция».

## 4. Единица наблюдения: что такое одна строка

**Это самый важный шаг.** Половина ошибок EDA — из-за того, что строка таблицы не совпадает
с объектом, о котором делается вывод.

В DVF строка — не сделка, а *сделка × участок × помещение × вид угодий*. Квартира с парковкой и погребом
занимает три строки, и **в каждой повторена полная цена сделки**. Если считать «цену за м²» по строкам,
цена одной сделки попадёт в выборку трижды, а у парковки будет «цена за м²» квартиры.

Как это обнаружить:

```python
# сколько строк на одну сделку
df.groupby("id_mutation").size().value_counts().head()

# одинакова ли цена внутри сделки
(df.groupby("id_mutation")["valeur_fonciere"].nunique() > 1).mean()

# что лежит внутри сделок с несколькими строками
df[df["id_mutation"] == df["id_mutation"].iloc[0]].T

# сколько жилых помещений в одной сделке
res = df[df["type_local"].isin(["Appartement", "Maison"])]
res.groupby("id_mutation").size().value_counts().head()
```

Вывод для DVF: цена за м² корректна только у сделок ровно с одним жильём и без коммерческих помещений.
Парковки и погреба продаются вместе с квартирой и входят в её цену.

Вопросы, которые стоит задать любой таблице:

- что является ключом и уникален ли он (`df.duplicated(key).sum()`);
- повторяются ли значения уровня «родителя» в строках «детей» (цена сделки в строках помещений);
- какая дата записана: событие, регистрация или выгрузка (в DVF — подписание у нотариуса, то есть
  на 2–4 месяца позже договорённости о цене).

## 5. Очистка с воронкой

### 5.1. Принципы

- **Каждое правило записано в коде и в воронке**: шаг → сколько сделок осталось.
- **Границы правдоподобия — по смыслу, а не по квантилям.** Квартира 5 м² или цена 200 €/м² в Париже
  не бывают; 1-й перцентиль — это просто 1 % данных.
- **Выбросы ищите робастно и внутри групп.** 30 000 €/м² — норма для 6-го округа и выброс для
  пригорода. Используйте медиану и MAD (медианное абсолютное отклонение), а не среднее и σ:
  σ сама раздувается выбросами.

### 5.2. Код (сокращённо, полностью — `src/dvf/clean.py`)

```python
funnel = [("строк в сыром DVF", len(raw)), ("сделок", raw["id_mutation"].nunique())]

df = raw[raw["nature_mutation"].isin(["Vente", "Vente en l'état futur d'achèvement"])]
funnel.append(("продажи", df["id_mutation"].nunique()))

g = df.groupby("id_mutation")
ok = (g["valeur_fonciere"].nunique() == 1) & (g["numero_disposition"].nunique() == 1)
# ... ровно одно жильё, нет коммерции → res
funnel.append(("одно жильё, без коммерции, одна цена", len(res)))

s = res[res["surface_reelle_bati"].between(9, 400)]
s["ppm2"] = s["valeur_fonciere"] / s["surface_reelle_bati"]
s = s[s["ppm2"].between(1_500, 40_000)]
funnel.append(("границы правдоподобия", len(s)))

# робастный z внутри коммуны и типа жилья
lp = np.log(s["ppm2"])
grp = [s["code_commune"], s["type_local"]]
med = lp.groupby(grp).transform("median")
mad = (lp - med).abs().groupby(grp).transform("median") * 1.4826   # 1.4826: MAD → σ для нормального
s = s[(lp - med).abs() <= 4 * mad.clip(lower=0.05)]
funnel.append(("без выбросов внутри коммуны", len(s)))
```

## 6. Одномерный анализ

Цель — понять форму каждой ключевой величины, а не нарисовать всё подряд.

```python
s["ppm2"].describe(percentiles=[.01, .05, .5, .95, .99])
np.log(s["ppm2"]).skew()                      # цены почти всегда скошены: смотрите на log-шкале
s.groupby("year").size()                      # объём по периодам
s["month"].value_counts().sort_index()        # сезонность объёма
(s["price"] % 1000 == 0).mean()               # «кучкование» на круглых числах (heaping)
```

Что проверить:

- **лог-шкала**: цены, доходы и площади почти всегда логнормальны, поэтому модели строятся на `log`;
- **кучкование (heaping)**: 69 % цен в DVF кратны 1 000 €, и это уже готовая гипотеза о психологии цены;
- **непрерывность во времени**: провалы в данных по месяцам (август), смена методики, неполный последний месяц.

## 7. Связи и разрезы

```python
s.groupby(["zone", "year"])["ppm2"].median().unstack()            # медиана по разрезам
s.groupby("size_bin", observed=True)["ppm2"].agg(["median", "size"])
s[["surface", "ppm2", "dist_km"]].corr(method="spearman")         # ранговая корреляция устойчива к выбросам
pd.crosstab(s["dep"], s["new_build"], normalize="index")          # доли категорий
```

**Ищите конфаундеры: общие причины двух величин.** Большие квартиры в пригороде «дороже» студий за м²,
но только потому, что они стоят в дорогих коммунах. Перед любым сравнением спросите:
«Чем ещё отличаются эти группы?»

Сколько разброса объясняет каждый фактор:

```python
from dvf.stats import design, fe_ols
fe_ols(y, design(f, ["ls"]), f["code_commune"]).r2_fe_only    # 0,75 — одна коммуна
fe_ols(y, X, f["cell"]).r2                                     # 0,82 — ячейка 300 м + характеристики
```

Если один фактор объясняет 80 %, все остальные сравнения нужно делать внутри него.

## 8. Гипотезы: как их формулировать

Шаблон для каждой гипотезы:

| Поле | Пример (новостройки) |
|---|---|
| **Гипотеза** | новостройка дороже вторички за м² |
| **Почему важно** | девелопер закладывает премию в цену, покупатель сравнивает варианты |
| **Метрика** | разница log(€/м²) новостроек и вторички |
| **Наивная оценка** | разница медиан: +1,9 % |
| **Чем может быть искажена** | новостройки строят в дешёвых районах (конфаундер — локация) |
| **Проверка** | регрессия с фиксированным эффектом ячейки 300 м, 95 % ДИ кластерный |
| **Результат** | +23,9 % [+22,1; +25,7], устойчиво по 3 департаментам |
| **Вывод** | наивное сравнение занижает премию в 13 раз |

Где брать гипотезы:

1. **Из предметной области**: ставки → цены, Олимпиада → цены рядом, пандемия → «эффект пончика».
2. **Из популярных утверждений**: «студии дороже за метр», «летом дороже».
3. **Из странностей, найденных на шагах 3–7**: кучкование цен, провал в августе.
4. **Механизм, а не только факт**: «объём падает сильнее цены» — это проверка липкости цен.

Записывайте гипотезу **до** проверки. Если формулировать её после того, как увидели график, любая
случайность станет «находкой».

Нулевой результат тоже публикуется. Олимпийского эффекта не найдено, и это честный, полезный вывод.

## 9. Статистическая проверка

### 9.1. Какой инструмент выбрать

| Вопрос | Инструмент | Функция |
|---|---|---|
| отличаются ли распределения двух групп | Манн — Уитни (непараметрический) | `scipy.stats.mannwhitneyu` |
| отличается ли частота категорий от ожидаемой | χ² | `scipy.stats.chisquare` |
| монотонная связь двух величин | ρ Спирмена | `scipy.stats.spearmanr` |
| различие средних по нескольким группам | ANOVA (F-тест) | `scipy.stats.f_oneway` |
| доверительный интервал медианы или любой статистики | бутстреп | `dvf.stats.boot_median` |
| эффект при прочих равных | регрессия (МНК) с контролями | `statsmodels`, `dvf.stats.fe_ols` |
| сравнение внутри групп (район, клиент) | фиксированный эффект | `dvf.stats.fe_ols(groups=...)` |
| наблюдения внутри группы зависимы | кластерные стандартные ошибки | `fe_ols(clusters=...)` |
| эффект события для нескольких единиц | разность разностей + перестановочный тест | `dvf.stats.permutation_did` |

### 9.2. Бутстреп: интервал для чего угодно

```python
rng = np.random.default_rng(0)
boot = [np.median(rng.choice(x, len(x))) for _ in range(2000)]
lo, hi = np.percentile(boot, [2.5, 97.5])
```

Если наблюдения сгруппированы (сделки внутри коммуны, дни внутри скважины), пересэмплируйте
**группы целиком**, иначе интервал будет слишком узким.

### 9.3. Регрессия с фиксированным эффектом

Сравнение «той же квартиры в том же месте»:

```
log(€/м²) = эффект ячейки + β·квартал + γ·log(площадь) + δ·комнаты + θ·новостройка + ε
```

Эффект ячейки (5 122 ячейки) не нужно вводить тысячами дамми. Вычтите средние по ячейке из y и из X
(внутригрупповое преобразование), это даёт те же коэффициенты:

```python
yd = y - y.groupby(groups).transform("mean")
Xd = X - X.groupby(groups).transform("mean")
beta = np.linalg.lstsq(Xd, yd, rcond=None)[0]
```

Через дамми в statsmodels это требует ~10 ГБ памяти, так — секунды. Сверка с эталоном —
в `tests/test_stats.py`.

Коэффициент лог-модели переводится в проценты так: `exp(β) − 1`.

### 9.4. Кластерные ошибки и когда они не работают

Сделки в одной ячейке похожи друг на друга, поэтому обычные стандартные ошибки занижены.
Кластерные ошибки это учитывают, но рассчитаны на **много кластеров в каждой сравниваемой группе**.
При трёх «экспериментальных» коммунах (Олимпиада) им нельзя доверять.

### 9.5. Перестановочный тест

Вопрос: выделяется ли наш набор из трёх коммун среди *всех возможных* наборов из трёх коммун?

```python
from itertools import combinations
placebo = [effect(combo) for combo in combinations(units, 3)]     # 7 140 наборов
p = np.mean(np.abs(placebo) >= abs(observed))
```

Тест не опирается на асимптотику и честен при малом числе единиц.

### 9.6. Плацебо-контроль

Сравните эффект в месте, где его быть не должно. «Чуть ниже порога» сделок больше и у 300 000,
и у 310 000, потому что плотность падает с ценой. Перевес у круглых порогов нужно сравнивать с
перевесом у некруглых: +12,8 % против +2,2 %.

### 9.7. p-value — не главное

На 300 тыс. наблюдений почти всё «значимо». Главное — **размер эффекта и интервал**: «+23,9 %
[+22,1; +25,7]», а не «p < 0,001». Сезонность цены значима (p < 0,001), но её размах всего 2,7 %, то
есть практически она мала.

Много проверок подряд дают ложные «находки» (из 20 тестов один при α = 0,05 сработает случайно).
Держите список гипотез коротким и заранее записанным, а при множестве сравнений используйте поправку
(Бонферрони или Холм: `statsmodels.stats.multitest.multipletests`).

| Ловушка | Как проявилась здесь | Защита |
|---|---|---|

## 11. Визуализация

### 11.1. Форма по задаче

| Задача | Форма |
|---|---|
| изменение во времени | линия; интервал — полупрозрачная полоса |
| сравнение категорий | горизонтальные столбцы, отсортированные по значению |
| эффект с интервалом | точка + «усы» (dot plot), вертикальная линия на нуле |
| связь двух величин | точечная диаграмма, подписи для выделяющихся точек |
| распределение | гистограмма с осмысленным шагом (1 000 € для цен) |
| география | точки на сетке (ячейки 300 м) или хороплет |
| одно ключевое число | карточка с числом, а не график |

### 11.2. Правила

- **Одна ось Y.** Две величины разного масштаба — это два графика или индекс к общей базе.
- **Цвет закреплён за сущностью**: Париж всегда синий, пригород — оранжевый, на всех графиках.
- **Последовательная шкала** (одна гамма от светлого к тёмному) — для величин; **расходящаяся**
  (два цвета и серый в центре) — для изменений со знаком.
- **Показывайте неопределённость**: полосы ДИ, «усы», коридор плацебо.
- **Наивное и правильное рядом**: пунктир «медианы как есть» против сплошной линии «в той же ячейке» —
  лучший способ показать ловушку.
- **Заголовок говорит вывод или вопрос**: «Чем дороже округ, тем меньше упал (ρ = 0,94)».
- Подписи осей в единицах (€/м², %), разделители тысяч, русская локаль (`separators=", "`).

### 11.3. Plotly: каркас функции графика

import plotly.graph_objects as go

def index_chart(t):

## 13. Тесты

Три уровня:

1. **Очистка на синтетике** (`tests/test_clean.py`). Маленькие таблицы с заранее известным ответом:
   «квартира + 2 парковки → одна сделка с полной ценой», «две квартиры в сделке → выброшена»,
   «выброс внутри коммуны → удалён».
2. **Статистика против эталона** (`tests/test_stats.py`). Свою FE-регрессию сверяем с регрессией на
   дамми из statsmodels до 1e-10. Перестановочный тест должен находить подложенный эффект и не
   находить шум.
3. **Выводы на реальных данных** (`tests/test_analysis.py`). Например, «премия новостроек внутри ячейки
   > 15 % и больше наивной». Если данных нет, такие тесты пропускаются (`pytest.mark.skipif`).

```bash
pytest -q                          # все тесты
pytest tests/test_stats.py -q      # один файл
pytest -k simpson -q               # по имени
```
